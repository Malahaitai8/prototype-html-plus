# 测试目标

验证 Step 2 的需求确认 / PRD Lite 能力是否按规则工作：先整理需求、标注缺口、最多追问 5 个阻塞问题、默认确认 PRD 后再进入原型，不直接生成 HTML。

# 测试输入

请用 `$prototype-html-plus` 处理以下 5 组输入，每组都单独测试：

```text
我想做一个数据更新看板。
```

```text
我要做一个 B 端清算单元管理页面，桌面 Web，高保真。需要搜索、筛选、表格、分页、新增按钮、查看详情，给前端评审用。
```

```text
我想做一个移动端会员积分页，帮我推荐。
```

```text
跳过，直接生成初版。我想做一个门店巡检小程序。
```

```text
我要做一个完整的供应链协同平台，包括首页、订单、库存、物流、供应商、审批、报表和消息通知。
```

# 预期行为

- 对模糊输入，先输出 PRD Lite 草案和最多 5 个阻塞追问，不生成 HTML。
- 对信息较完整的输入，填充 PRD Lite，标记少量待确认项，并要求用户确认。
- 对“帮我推荐”，推荐内容必须标记为 `Agent 假设`。
- 对“跳过，直接生成初版”，只输出 PRD 草案和假设，不直接生成 HTML。
- 对大范围需求，必须输出原型分步计划，建议先做主路径初版。
- 用户回答追问后，必须重新输出完整更新后的 PRD Lite，并询问是否确认、是否保存 `requirements.md`、是否进入 Step A。
- 即使用户说“按推荐继续”，也不能自动生成 HTML 或保存文件，除非用户明确授权。

# 预期产物

- Markdown 格式 `原型 PRD Lite`。
- 每个关键部分包含 `已确认` / `待确认` / `Agent 假设` 状态。
- 包含设计参考路由，例如 B 端、C 端、H5、App、小程序等对应参考。
- 包含 `原型分步计划`。
- 包含 `设计原则与边界`。
- 包含 `分步执行协议`。
- 包含需要用户确认的问题。

# 人工验收点

- Agent 没有假设存在真实交互表单。
- Agent 没有在需求确认阶段生成 HTML。
- 每轮追问不超过 5 个阻塞问题。
- 大需求没有被要求一次性做完整原型。
- 如建议保存 `requirements.md`，必须先征求用户确认。
- PRD 中的分步计划必须被当成执行队列：默认一次只做当前步骤，做完验收后再进入下一步。
- 所有产品类型都必须确认设计原则和风险边界；C 端、情绪化、游戏化、健康、金融、儿童、教育等场景需要更仔细。

# 失败表现

- 直接生成 HTML。
- 只问散乱问题，没有 PRD Lite。
- 没有标记 `已确认` / `待确认` / `Agent 假设`。
- “帮我推荐”的推荐项没有标记为假设。
- “跳过初版”直接进入 HTML 实现。
- 对复杂平台一次性承诺做完整多页面原型。
- 用户回答追问后没有回显完整更新版 PRD。
- 未经确认就保存 `requirements.md`。
- PRD 写了分步计划，但后续默认一次性执行多个步骤。
